## P0 — блокеры (это первым, остальное после)

### F0a. В файле два разных способа рисовать группу набора

**Сейчас.** `k: 'cset'` — заголовок без кнопки, компоненты отдельными строками со своими кнопками и статусами: `g-multi`, `g-single`, `g-kitchens`, `g-assembly`, `g-between` (5 экранов). `k: 'combo'` — блок с **одной кнопкой статуса на всю группу** (`kds-kit__btn`), компоненты текстом без статусов и действий: `base`, `g-courses`, `g-instances`, `g-instances-same`, `g-modifier`, `g-cancelled`, `g-long` (7 экранов).

**Причина.** `comboGroup` построена на виде блюда с модификаторами из макета (см. F0b) — отсюда и кнопка на всю группу, и количество у компонентов, и комментарий. Для набора этот вид неверен по определению.

**Почему блокер.** На семи экранах у набора есть действие и признак статуса — прямое нарушение условий 1 и 2 постановки («у набора нет количества, статуса, времени и действий», «заголовок набора не имеет состояний статуса»). Один и тот же набор в двух местах ведёт себя по-разному.

**Сделать.** Оставить один рендер — `cset`. Все состояния, кроме `base`, перевести на него. Функцию `comboGroup` удалить.

**Критерий.** Кроме `base`, ни у одной группы нет кнопки, статуса и количества; `k: 'combo'` в файле встречается только внутри `base`.

---

### F0b. «Комбо с пастой» — блюдо с модификаторами, а не набор

**Подтверждено дизайнером (22.10.2026): «Комбо с пастой» в макете — блюдо с модификаторами.** Название содержит слово «комбо», но сущность — обычное блюдо: у него есть количество у модификаторов («1 Паста карбонара», «1 Капучино»), комментарий и одна кнопка 52×162 на всю высоту блока. Всё это законно для блюда и незаконно для набора.

**Что из этого следует.**
- База `base` **не трогается**: там блюдо с модификаторами, нарисованное правильно. Перерисовывать и «убирать кнопку» нельзя.
- `comboGroup` — функция, построенная на виде блюда с модификаторами, — для набора не годится вовсе. Удалить (это часть F0a).
- Строку «Комбо с пастой» в `d-list` нельзя показывать как набор: это блюдо с модификаторами, как «Пицца от шефа». Подпись «Комбо: …» к ней не относится.
- Во всех текстах прототипа заменить формулировки «комбо-блок», «набор в карточке (Figma 10585:7793)» на «блюдо с модификаторами»: в шапке файла, в аннотации `base`, в комментарии к `comboGroup`.

**Критерий.** В файле нигде не утверждается, что блок «Комбо с пастой» — набор; `base` визуально не изменилась; «Комбо с пастой» в `d-list` оформлено как блюдо с модификаторами.

## P1 — обязательные правки

### F1. Режим «по блюдам»: убрать комбо-строку с раскрытым составом

**Сейчас.** Состояние `d-list`. Комбо нарисовано отдельной строкой `kds-dl-main--combo` с названием «Комбо с пастой», составом чипами («Паста карбонара», «Капучино») и комментарием. Класс тот же, что у списка модификаторов, поэтому комбо читается как блюдо с модификаторами.

**Почему это ошибка.** В задаче: «компактное текстовое указание принадлежности у строки блюда, **без показа остальных компонентов набора**». Плюс набор становится отдельной строкой в потоке блюд, чего у него быть не может.

**Сделать.**
- «Комбо с пастой» оставить как в макете: это блюдо с модификаторами, а не набор — оно рисуется строкой блюда, как «Пицца от шефа». Подпись «Комбо: …» к нему не добавлять.
- Удалить строку-контейнер, которая изображает **набор** в плоском списке.
- У каждой строки блюда, входящего в набор, — вторичная подпись под названием: `Комбо: <название>`, при нескольких экземплярах — `Комбо: <название> №<экземпляр>`. Размер 12/16, цвет `#9E9E9E`, шрифт тот же.
- Состав набора не выводить ни чипами, ни текстом, ни в комментарии.
- Порядок и количество строк в списке не меняются: одна позиция — одна строка.

**Критерий.** В `d-list` нет элемента с составом набора; у каждой позиции набора есть подпись «Комбо: …»; число строк равно числу блюд; название, количество, статус и время остаются первыми по порядку чтения.

### F2. «Видно N из M» — считать по карточке, а не внутри курса

**Сейчас.** `seen = (g.rows || []).length` сравнивается с `g.total` (общее число на набор). На `g-courses` в курсе 1 подпись «видно 1 из 3 позиций набора», в курсе 2 — «видно 2 из 3», хотя все три компонента на этой же карточке (суп в первом курсе). Два противоречащих сигнала на одной карточке.

**Сделать.** Считать `N` как число строк этого экземпляра набора, видимых **на всей карточке** (по всем курсам), `M` — общее число позиций экземпляра. Показывать подпись только когда `N < M`. При разложении по курсам на каждой группе должно стоять одно и то же значение.

**Критерий.** `g-courses`: в обоих курсах одна и та же подпись и она указывает на полный набор (3 из 3) либо подписи нет; `g-multi` — 2 из 3; `g-single` — 1 из 3; на `base` подписи нет.

### F3. Экземпляр набора — номером, не цветом

**Сейчас.** В шапке файла заявлен «порядковый номер экземпляра (1., 2.)», на экранах — маджента и циан: цветная точка (`g-instances`) и залитый прямоугольник (`g-instances-same`). Цвет — единственный носитель различия, маджента и циан не из палитры КДС, а цвет в интерфейсе занят статусами.

**Почему это ошибка.** Задача прямо требует: «цвет не является единственным носителем связи». Плюс обоснование на экране `rationale` утверждает обратное — «цвет занят статусами блюд».

**Сделать.**
- Убрать цветные точки и плашки полностью.
- Порядковый номер экземпляра — текстом сразу после названия: `Ланч №1`, `Ланч №2`. Формат: 14/20, цвет `#BDBDBD`, не жирный.
- Показывать номер только если в заказе больше одного экземпляра этого набора; при единственном — не показывать.
- Номер одинаков во всех курсах и на всех экранах.

**Критерий.** В `g-instances` и `g-instances-same` нет цветных маркеров; номера совпадают между курсами; при одном экземпляре номера нет; различие читается без цвета.

### F4. Длинное название: многоточие и доступ к полному имени по тапу

**Сейчас.** `g-long` (720 px). Заголовки групп обрезаны по 161 px при содержимом 258 px, `text-overflow: clip` — без многоточия, оба названия в видимой части идентичны. Раскрытие по нажатию (`data-full`) реализовано только в `dishRow`, у заголовков набора атрибута нет, поэтому полное имя недоступно. Аннотация при этом обещает «на мыши — наведением», хотя экран тач.

**Сделать.**
- Заголовку группы добавить `text-overflow: ellipsis` и `white-space: nowrap` с `overflow: hidden`.
- Добавить заголовку `data-full="<полное название>"` и подключить к существующему обработчику нажатия.
- Раскрытие — по нажатию на всю строку заголовка (высота цели ≥ 44 px), авто-скрытие через 3 с. Никаких hover-зависимостей.
- При раскрытии не менять высоту остальных строк: показывать полное имя поверх (поповер) либо в одну строку с переносом внутри заголовка.

**Критерий.** На `g-long` оба названия заканчиваются многоточием, видимые части различаются; тап открывает полное имя; после авто-скрытия раскладка не сдвигается; в аннотации нет упоминания наведения.

### F5. Пиктограммы: звезда занята, набору нужна своя

**Сейчас.** Постер `icons` утверждает: «знак набора — зелёная звезда в круге: она уже стоит у набора». Это неверно дважды. Во-первых, в макете звезда стоит у **блюда с модификаторами** («Комбо с пастой»). Во-вторых, **звезда в продукте означает «новое блюдо»** — это подтверждено дизайнером 22.10.2026. Значит для набора звезда занята и использовать её нельзя. На экране `g-modifier` иконки нет вовсе.

**Сделать.**
- **Снять звезду со всех заголовков групп набора.** Данные `star: true` у группы и рендер звезды в `csetGroup` убрать целиком. Звезда остаётся только у строк блюд, где означает новое блюдо (в `base` она на «Комбо с пастой» именно за этим).
- **Постер `icons` переделать под реальность:** три сущности — «новое блюдо» (звезда, не трогаем), «входит в набор» (пиктограмма **не выбрана**, это открытый вопрос №9 постановки), «блюдо с отдельно готовящимся модификатором» (пиктограмма **не выбрана**, кандидат `post_add`).
- **На время до решения** группу набора не помечать никакой пиктограммой: только название, как сейчас на `g-multi`.
- Убрать из постеров и аннотаций утверждения, что звезда обозначает набор.

**Критерий.** Звезды нет ни на одной группе набора во всех состояниях; на постере три разные сущности с честными статусами иконок («есть» / «не выбрана»); `base` не изменилась; в текстах нет фразы «звезда — знак набора».

### F6. Показать исходный порядок, который меняется при сборке группы

**Сейчас.** `g-between`: группа собрана одним блоком, салат, стоявший между компонентами, оказался выше группы. Решение в пользу целостности против сохранения порядка принято, но не названо, и исходный порядок не виден — выглядит так, будто порядок сохранён.

**Сделать.**
- Добавить состояние `g-between-order` — «как пришло из заказа»: строки в исходном порядке (бургер, салат, картофель), с пометкой принадлежности у компонентов и без группировки.
- На `g-between` добавить в аннотацию одну фразу: группа собрана целиком, поэтому порядок внутри курса отличается от исходного.
- Оба состояния зарегистрировать в `layouts.js` подряд.

**Критерий.** Разница между «как пришло» и «как собрано» видна глазами; в аннотации назван компромисс.

## P2 — незакрытые открытые вопросы

### F7. Группа: без подложек и фонов (признак группы — отложен)

**Статус: отложено.** Дизайнер решил: подложки и фоны не нужны — ни у группы, ни у блюд. Пункт в прежней редакции (контейнер с заливкой `#1C1C1C`) отменён. Чем отличать группу вместо фона — пока не решено, к этому вернутся после того, как применятся остальные правки. **Сейчас по F7 делать только одно: не добавлять ничего.**


**Сейчас.** Замер: строка внутри группы — `x=79`, ширина 210; обычная строка — `x=64`, ширина 225. Фон у обеих `#212121`, радиус 8, у контейнера группы нет ни рамки, ни подложки. Единственный признак принадлежности — 15 px отступа и заголовок.

**Сделать.** Оставить вид базы: у контейнера группы нет заливки, рамки, тени и отступа-подложки. Отступ вложенных строк — как в макете (16). Принадлежность читается заголовком группы и отступом, больше ничем.

**Не делать.** Не добавлять заливки, тонирования, плашки, обводки, рейлы, градиенты — ни группе, ни строкам, ни заголовку.

**Открыто (решает дизайнер, не агент).** Признак группы без подложки обсуждается позже: линия-связка, разделитель или усиление заголовка. До решения — ничего не добавлять и вопрос не поднимать, просто оставить вид базы.

**Критерий.** В коде нет ни одной новой заливки, рамки или тени у контейнера группы и у строк; визуально строки группы совпадают со строками `base`.

### F8. Подпись частичной видимости легко прочесть как готовность

**Сейчас.** Текст «видно 2 из 3 позиций набора», 12/16, `#9E9E9E`. Рядом с строками блюд, у которых видны статусы, дробь читается как прогресс — особенно на холодном цехе, где «1 из 3» похоже на «сделано 1 из 3».

**Сделать.** Переформулировать без счётной дроби прогресса: `на экране 2 из 3 блюд набора` и, если места хватает, второй строкой `остальные — в других цехах`. Цвет поднять до `#BDBDBD` (контраст на тёмном фоне), размер оставить 12/16.

**Критерий.** Формулировка не содержит слов «готово», «собрано», «выполнено»; смысл — видимость, а не статус.

Добавить и зарегистрировать в `layouts.js`:

## P3 — оформление, реестр, честность описания

## Требования к данным, без которых правки не сделать

Эти поля нужны от бэкенда (DS-1576) — агент не должен их вычислять из видимого списка:

| Поле | Зачем | Сейчас в задаче |
|---|---|---|
| `comboTotal` — общее число позиций экземпляра набора | подпись «на экране N из M» | нет |
| `comboInstance` — порядковый номер экземпляра (1..N), стабильный в пределах заказа | различение двух одинаковых наборов | есть как «признак», вид не задан |
| `comboId` — идентификатор экземпляра | группировка в режиме «по заказам» | есть |
| `comboName` — полное название набора | сокращение + доступ к полному | есть |
| `modifierParentDishId` — родительское блюдо модификатора | связь «к Бургеру» | есть частично |
| `modifierIsSeparateTask` — модификатор готовится отдельно | вторичная подпись связи; пиктограмма — кандидат `post_add`, не утверждена | нет |
| `cancelled` — признак отмены компонента | зачёркивание, исключение из комплекта | есть |

**Чего делать нельзя:** генерировать цвет экземпляра на клиенте; считать `comboTotal` по числу видимых строк; показывать номер экземпляра, если в заказе он один.
